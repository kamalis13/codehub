Module 2 — Components

Dynamic Components

Creating and injecting components at runtime using ViewContainerRef

📌 Definition

Dynamic components are Angular components created imperatively at runtime via ViewContainerRef.createComponent(ComponentClass), rather than declared statically in a template. Angular instantiates the component, creates its host DOM element, runs its change detection, and inserts it into the specified container. The caller receives a ComponentRef<T> that gives programmatic access to the component's instance, DOM element, and lifecycle.

🤔 Why is it needed?

  • Toast / notification systems — Create transient UI elements on demand without polluting the static template.
  • Modal dialogs — Render modals from anywhere in the app without a static placeholder.
  • Plugin / widget systems — Load and render component types determined at runtime (e.g., from a CMS or registry).
  • Lazy rendering — Combine with lazy loading to create component types that aren't bundled until needed.
  • Code splitting — Dynamically import a component file, then create it, keeping the initial bundle lean.

🌐 Real-time Example

    

      A ToastService holds a reference to a ViewContainerRef registered
      by AppComponent. Any component in the app injects ToastService and calls
      show('File saved!', 'success'). The service creates a ToastComponent
      dynamically, sets its @Input properties directly on ref.instance, and
      schedules ref.destroy() after 3 seconds — all without any static template wiring.
    

    

  


  

    
⚙️ Internal Working

    

      ViewContainerRef represents a logical position in the DOM where views can be inserted.
      createComponent() uses Angular's internal component factory to: (1) instantiate the
      component class and resolve its dependencies via the injector; (2) create the component's host DOM
      element; (3) initialize change detection for the new component; (4) insert the host element as
      a sibling after the container anchor comment node. Before Angular 13, this required
      ComponentFactoryResolver. Modern Angular (13+) accepts the component class directly.
      Standalone components work seamlessly since they self-declare their dependencies.
    

  


  

    

      
✅ Advantages

      
    
        
  • Full runtime flexibility — component type can be decided at runtime
    • 
        
  • Enables centralized notification / overlay systems
    • 
        
  • Works with lazy loading for optimal code splitting
    • 
        
  • Complete lifecycle control (create, update inputs, destroy)
    • 
        
  • No need for global *ngIf placeholders throughout the template
    • 
      

    

    

      
❌ Disadvantages

      
    
        
  • More complex than static template declarations
    • 
        
  • Must manually trigger change detection for OnPush components after input assignment
    • 
        
  • Memory leaks if ref.destroy() is not called
    • 
        
  • Bypasses Angular's declarative template model — harder to reason about
    • 
        
  • Debugging is harder — component doesn't appear in the static template
    • 
      

    

  


  

    
🏆 Best Practices

    
    
      
  • Always call ref.destroy() when the dynamic component is no longer needed.
    • 
      
  • Use a central <ng-container #host></ng-container> as the injection point for global overlays.
    • 
      
  • For OnPush dynamic components, call ref.changeDetectorRef.detectChanges() after setting inputs.
    • 
      
  • Combine with import() for lazy loading: const { MyComp } = await import('./my.component'); vcr.createComponent(MyComp);
    • 
      
  • Encapsulate the creation logic in a service so components don't directly depend on ViewContainerRef.
    • 
    

  


  

    
⚠️ Common Mistakes

    
    
      
  • Forgetting to call ref.destroy() — causes memory leaks and orphaned DOM nodes.
    • 
      
  • Accessing @ViewChild container before ngAfterViewInit — it will be undefined.
    • 
      
  • Setting inputs after creation without calling detectChanges() on an OnPush component — the view won't update.
    • 
      
  • Using the deprecated ComponentFactoryResolver in Angular 13+ — use createComponent(ComponentClass) directly.
    • 
      
  • Creating dynamic components without providing the correct EnvironmentInjector — dependencies fail to resolve.
    •
