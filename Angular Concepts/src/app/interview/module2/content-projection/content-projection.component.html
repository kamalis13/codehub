Content Projection (ng-content)

Inserting consumer-provided HTML into a reusable component shell

📌 Definition

Content projection is an Angular pattern that lets a parent component insert arbitrary HTML content into predefined slots (<ng-content>) inside a child component's template. The child defines where the projected content appears; the parent decides what content goes there. This enables the creation of highly reusable container components — cards, modals, tabs, accordions — without requiring the consumer to pass every bit of content through @Input properties.

🤔 Why is it needed?

  • Reusable shells — Define chrome (borders, padding, backdrop) once; let consumers fill in the content.
  • Flexible composition — Consumers can project any HTML, components, or directives without the host needing to know about them in advance.
  • Avoids @Input explosion — Instead of @Input() headerHtml, @Input() bodyHtml, etc., consumers project real Angular templates with data bindings.
  • Declarative layout — Named slots (select attribute) create a clear, semantic layout contract between the component and its consumers.

🌐 Real-time Example

    

      A reusable ModalComponent defines three named slots using attribute selectors:
      [modal-header], [modal-body], and [modal-footer].
      Consumers project any content — headings, paragraphs, forms, or action buttons — into these
      slots. The modal itself handles opening, closing, overlay, and animation, remaining completely
      content-agnostic.
    

    

  


  

    
⚙️ Internal Working

    

      Angular implements content projection using the light DOM concept. Projected
      content is not part of the host component's view — it remains in the parent's DOM tree
      and is governed by the parent's change detector. When Angular renders
      <ng-content>, it physically moves the projected DOM nodes into that location.
      The select attribute accepts any valid CSS selector (element, attribute, class).
      Content that doesn't match any selector is discarded. This differs from Shadow DOM, which uses
      browser-native encapsulation — Angular's default Emulated encapsulation mimics
      Shadow DOM scoping without using it.
    

  


  

    

      
✅ Advantages

      
    
        
  • Enables genuinely reusable, slot-based container components
    • 
        
  • Projected templates can contain full Angular bindings and directives
    • 
        
  • Named slots provide a clear, discoverable component API
    • 
        
  • Reduces the need for many @Input properties for content
    • 
        
  • Works with @ContentChild for host-projected coordination
    • 
      

    

    

      
❌ Disadvantages

      
    
        
  • Unmatched projected content is silently discarded — no error
    • 
        
  • Cannot apply *ngIf directly on <ng-content>
    • 
        
  • Projected content's change detection is owned by the parent, not the host
    • 
        
  • Complex slot contracts can be hard to discover without documentation
    • 
      

    

  


  

    
🏆 Best Practices

    
    
      
  • Document each <ng-content> slot with a comment explaining its expected content.
    • 
      
  • Use attribute selectors (select="[slot-name]") over component selectors for greater consumer flexibility.
    • 
      
  • Add a default <ng-content> (no selector) to capture unslotted content.
    • 
      
  • For conditional slots, use a wrapper: <div *ngIf="hasHeader"><ng-content select="[header]"></ng-content></div>.
    • 
      
  • Prefer content projection over @Input() html: string — projecting real templates is safer (avoids XSS) and richer.
    • 
    

  


  

    
⚠️ Common Mistakes

    
    
      
  • Applying structural directives (*ngIf) directly to <ng-content> — this is not allowed.
    • 
      
  • Expecting the host to control projected content's change detection — it belongs to the parent.
    • 
      
  • Using multiple unselected <ng-content> tags — only one default slot is allowed.
    • 
      
  • Not checking what happens to unmatched content — it disappears silently.
    • 
      
  • Projecting sensitive user data as raw HTML from a service — always sanitize or prefer Angular template expressions.
    •
