Module 6 — Pipes

Async Pipe

Auto-subscribe to Observables and Promises — no manual cleanup required

📌 Definition

The async pipe automatically subscribes to an Observable or Promise and returns its latest emitted value. When the component is destroyed (or the template section is removed), the async pipe automatically unsubscribes, preventing memory leaks. It is an impure pipe that checks for new emissions on every change detection cycle. It is the recommended way to consume Observables in Angular templates.

🤔 Why is it needed?

  • Eliminates manual subscribe() in ngOnInit and unsubscribe() in ngOnDestroy
  • Prevents memory leaks — auto-unsubscription on component destroy
  • Enables reactive templates — data flows from Observable directly to view
  • Works seamlessly with *ngIf as to unwrap Observable into local template variable
  • Pairs naturally with OnPush change detection for optimal performance

⚙️ Internal Working

    
The AsyncPipe class implements PipeTransform and OnDestroy. On first transform() call, it stores the Observable/Promise reference and calls subscribe() (or .then()). Each emission updates an internal latestValue field and calls changeDetectorRef.markForCheck() to trigger a re-render. On ngOnDestroy, it calls subscription.unsubscribe(). It is impure — transform() is called every CD cycle to return the latest cached value.

  


  

    

      
✅ Advantages

      
    
        
  • Automatic unsubscription — zero memory leaks from forgotten cleanups
    • 
        
  • Cleaner component code — no subscription management boilerplate
    • 
        
  • Works with *ngIf as for elegant null-safe template access
    • 
        
  • Pairs with OnPush — only triggers CD when Observable emits
    • 
        
  • Works with both Observables and Promises
    • 
      

    

    

      
❌ Disadvantages

      
    
        
  • Multiple | async on the same Observable = multiple subscriptions
    • 
        
  • Cannot react to emissions in component class — only in template
    • 
        
  • Null/undefined initial state requires *ngIf guard or nullish coalescing
    • 
        
  • Error handling needs catchError in the pipe chain (template errors are cryptic)
    • 
      

    

  


  

    
🏆 Best Practices

    
    
      
  • Use *ngIf="obs$ | async as data" to subscribe once and expose local variable
    • 
      
  • Prevent multiple subscriptions with shareReplay(1) on shared Observables
    • 
      
  • Use the ViewModel pattern (combineLatest) to merge multiple streams into one vm$
    • 
      
  • Add catchError to your Observable chain to handle errors gracefully in the template
    • 
      
  • Prefer async pipe over manual subscribe in templates — always
    • 
    

  


  

    
⚠️ Common Mistakes

    
    
      
  • Using | async multiple times for the same Observable — creates multiple subscriptions
    • 
      
  • Forgetting *ngIf guard — the template renders before the Observable emits (null errors)
    • 
      
  • Not handling errors in the Observable chain — template shows blank on error
    • 
      
  • Mixing async pipe with manual subscriptions on the same Observable — double execution
    • 
      
  • Forgetting to import AsyncPipe or CommonModule in standalone components
    •
