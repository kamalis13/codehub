Pure vs Impure Pipe

Understand pipe execution strategy — the hidden performance lever in Angular

📌 Definition

Every Angular pipe is either pure or impure. A pure pipe (default, pure: true) only re-executes when its input value changes by reference — Angular caches the result and reuses it until a new reference is detected. An impure pipe (pure: false) re-executes on every change detection cycle, regardless of whether the input changed. The async pipe is a well-known impure pipe.

🤔 Why is it needed?

  • Pure pipes provide significant performance optimization through memoization
  • Impure pipes are necessary when input data is mutated without changing object reference
  • Understanding this distinction prevents subtle bugs (pipe not updating) and performance issues
  • The async pipe must be impure to check for new Observable emissions every cycle
  • Forces better patterns — immutable data with pure pipes leads to more predictable state

⚙️ Internal Working

    
During Angular change detection, for each pipe binding in a template, Angular checks if the pipe is pure or impure. For pure pipes: it compares the current inputs to the previous inputs using ===. If equal, it skips calling transform() and returns the cached result. For impure pipes: transform() is called on every single change detection run — even if the component's own state hasn't changed. This is why impure pipes can severely impact performance in large applications.

  


  

    

      
✅ Advantages

      
    
        
  • Pure pipe: Excellent performance — memoized, only runs when needed
    • 
        
  • Pure pipe: Predictable — runs deterministically based on input references
    • 
        
  • Impure pipe: Always reflects current state — no stale data
    • 
        
  • Impure pipe: Necessary for Observable-driven transforms (async pipe)
    • 
        
  • Both integrate with Angular's change detection automatically
    • 
      

    

    

      
❌ Disadvantages

      
    
        
  • Pure pipe: Misses mutations inside arrays/objects (no new reference)
    • 
        
  • Impure pipe: Runs on every CD cycle — severe performance impact for complex transforms
    • 
        
  • Impure pipe: Easy to accidentally create performance bottlenecks
    • 
        
  • Pure pipe: Requires immutable data patterns (might need refactoring)
    • 
      

    

  


  

    
🏆 Best Practices

    
    
      
  • Always prefer pure pipes (the default) — they are optimized by design
    • 
      
  • Use immutable array/object updates ([...arr, newItem]) to trigger pure pipe re-evaluation
    • 
      
  • Move complex filtering/transformation to the component class, not an impure pipe
    • 
      
  • If you must use an impure pipe, make the transform() as lightweight as possible
    • 
      
  • Avoid making API calls or heavy computation inside any pipe (pure or impure)
    • 
    

  


  

    
⚠️ Common Mistakes

    
    
      
  • Creating an impure pipe for filtering mutable arrays — use immutable updates instead
    • 
      
  • Doing expensive computation (HTTP, complex sorting) inside an impure pipe
    • 
      
  • Not understanding why a pure pipe appears "stuck" — the array/object reference didn't change
    • 
      
  • Assuming async pipe is pure — it is impure by necessity (checks every CD cycle)
    • 
      
  • Using impure pipes in components with Default change detection at scale — major perf hit
    •
