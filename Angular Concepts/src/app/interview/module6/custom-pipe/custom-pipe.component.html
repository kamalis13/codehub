Module 6 — Pipes

Custom Pipe

Create reusable data transformation functions for your templates

📌 Definition

A Custom Pipe is a user-defined pipe created with the @Pipe decorator that implements the PipeTransform interface. You define a transform(value, ...args) method that receives the piped value and optional arguments, and returns the transformed result. Custom pipes enable reusable template-level data transformations like truncating text, formatting phone numbers, converting relative times, and more.

🤔 Why is it needed?

  • Reuse data transformation logic across many templates without duplication
  • Keep transformation logic out of component class and template expressions
  • Angular's built-in pipes don't cover all business requirements (e.g., phone format, truncate)
  • Pure custom pipes are memoized — efficient even in large lists
  • Configurable via pipe arguments — one pipe, many behaviors

⚙️ Internal Working

    
Angular's template compiler identifies | pipeName expressions and replaces them with calls to the pipe's transform() method during template compilation. At runtime, Angular creates a pipe instance (or reuses it as a singleton in many cases) and calls transform(value, ...args) during change detection. Pure pipes cache the result by storing the previous inputs — if unchanged, the cached output is returned without calling transform() again.

  


  

    

      
✅ Advantages

      
    
        
  • Reusable across the entire application with zero code duplication
    • 
        
  • Pure pipes are memoized — very efficient even in *ngFor loops
    • 
        
  • Configurable via arguments — flexible, single-purpose design
    • 
        
  • Testable in isolation — just unit test the transform() method
    • 
        
  • Integrates with Angular DI — can inject services into pipes
    • 
      

    

    

      
❌ Disadvantages

      
    
        
  • Cannot directly use in component class code without DI injection
    • 
        
  • Impure pipes in *ngFor can severely impact performance
    • 
        
  • Transform errors in templates produce cryptic error messages
    • 
        
  • Each pipe is a separate class/file — adds to project file count
    • 
      

    

  


  

    
🏆 Best Practices

    
    
      
  • Always implement PipeTransform for proper TypeScript type checking
    • 
      
  • Handle null and undefined inputs defensively — always check before processing
    • 
      
  • Keep pipes pure (default) — use immutable inputs to trigger re-evaluation
    • 
      
  • Organize custom pipes in a shared/pipes/ folder for discoverability
    • 
      
  • Write unit tests for the transform() method — it is a plain function, easy to test
    • 
    

  


  

    
⚠️ Common Mistakes

    
    
      
  • Forgetting to handle null/undefined in transform() — causes template errors
    • 
      
  • Making a pipe impure without measuring the performance impact first
    • 
      
  • Doing expensive computation or HTTP calls inside the transform() method
    • 
      
  • Forgetting to import the pipe in the component's imports array (standalone)
    • 
      
  • Using new MyPipe().transform(val) in component code instead of DI injection
    •
