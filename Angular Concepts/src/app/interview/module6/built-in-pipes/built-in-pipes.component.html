Module 6 — Pipes

Built-in Pipes

Transform data in templates — format dates, numbers, strings, and more

📌 Definition

Angular built-in pipes are pre-built data transformation functions that format values directly in templates using the | operator. They transform display values without changing the underlying data. Available pipes include: date, currency, number, percent, uppercase, lowercase, titlecase, slice, json, keyvalue, and async. Pipes can be chained using multiple | operators.

🤔 Why is it needed?

  • Format data for display without polluting component logic with formatting code
  • Reusable — one pipe declaration works across the entire application
  • Declarative in templates — {{ price | currency }} is self-documenting
  • Localization support via LOCALE_ID (date, currency, number pipes)
  • Async pipe handles Observable subscriptions and cleanup automatically

⚙️ Internal Working

    
Angular evaluates pipe expressions during the template rendering phase of change detection. Each pipe is a class implementing PipeTransform with a transform(value, ...args) method. Pure pipes (the default) are only called when the input reference changes. Impure pipes run on every change detection cycle. Angular optimizes by caching pure pipe results — if the input hasn't changed, the previous output is reused.

  


  

    

      
✅ Advantages

      
    
        
  • Clean separation of formatting from business logic
    • 
        
  • Pure pipes are highly optimized — cached results, no unnecessary re-computation
    • 
        
  • Built-in pipes cover most common formatting needs out of the box
    • 
        
  • Localization support via Angular i18n for date, number, currency
    • 
        
  • Chainable — compose multiple transformations in one expression
    • 
      

    

    

      
❌ Disadvantages

      
    
        
  • Pipe transform errors can be hard to debug (template errors are cryptic)
    • 
        
  • Complex chained pipes reduce template readability
    • 
        
  • Cannot use pipes in @Component class code — must use DI injection pattern
    • 
        
  • Some pipes (async) are impure and run every change detection cycle
    • 
      

    

  


  

    
🏆 Best Practices

    
    
      
  • Use the async pipe instead of manual Observable subscriptions in templates
    • 
      
  • Prefer date:'medium' over complex custom format strings for readability
    • 
      
  • Use json pipe for debugging — remove it before production
    • 
      
  • Inject and use pipes in services when needed in component code (not just templates)
    • 
      
  • Chain pipes sparingly — for complex transformations, compute in the component
    • 
    

  


  

    
⚠️ Common Mistakes

    
    
      
  • Using {{ date | date }} on a string — pass a Date object or timestamp
    • 
      
  • Expecting pipes to update on mutable object property changes (use new references)
    • 
      
  • Using json pipe in production templates — exposes data structure
    • 
      
  • Forgetting to import CommonModule or specific pipe classes in standalone components
    • 
      
  • Chaining too many pipes in one expression — extract to a component getter instead
    •
