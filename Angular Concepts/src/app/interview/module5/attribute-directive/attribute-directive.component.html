Module 5 — Directives

Attribute Directive

Change the look and behavior of existing elements without touching the DOM structure

📌 Definition

An Attribute Directive changes the appearance or behavior of an existing DOM element, component, or directive. It is applied as an HTML attribute and does not add or remove DOM elements. Built-in attribute directives include ngClass and ngStyle. Custom attribute directives use @HostListener for event handling and @HostBinding for property binding on the host element.

🤔 Why is it needed?

  • Add reusable behavior to any element without wrapping it in a component
  • Dynamically apply CSS classes and inline styles based on component state
  • Listen to host element events (hover, click, focus) without touching the DOM directly
  • Bind to host element properties (aria attributes, classes, styles) declaratively
  • Encapsulate UI behavior (tooltip, highlight, drag-and-drop) as a reusable directive

⚙️ Internal Working

    
Angular's compiler identifies all @Directive selectors in the component's imports (or NgModule declarations). When a matching attribute is found in the template, Angular creates an instance of the directive class, injecting the host's ElementRef and any other DI tokens. @HostBinding sets up property bindings on the host element during change detection. @HostListener registers DOM event listeners that call the decorated methods. The directive participates in the full component lifecycle (ngOnInit, ngOnDestroy, etc.).

  


  

    

      
✅ Advantages

      
    
        
  • Lightweight — no template, no view overhead
    • 
        
  • Highly reusable — apply to any element type
    • 
        
  • Encapsulates event handling cleanly via @HostListener
    • 
        
  • Works with Angular's DI, change detection, and lifecycle hooks
    • 
        
  • Avoids direct DOM manipulation (ElementRef.nativeElement)
    • 
      

    

    

      
❌ Disadvantages

      
    
        
  • Cannot render its own template (no HTML output)
    • 
        
  • Complex logic can become hard to test without a host element
    • 
        
  • Multiple directives on one element can interact unexpectedly
    • 
        
  • Debugging @HostBinding issues can be tricky without DevTools
    • 
      

    

  


  

    
🏆 Best Practices

    
    
      
  • Prefer @HostBinding over directly accessing ElementRef.nativeElement
    • 
      
  • Use a consistent naming convention: appDirectiveName to avoid conflicts
    • 
      
  • Make directives configurable via @Input() for reusability
    • 
      
  • Clean up DOM event listeners or subscriptions in ngOnDestroy
    • 
      
  • For SSR compatibility, avoid direct browser APIs — use Renderer2 as a fallback
    • 
    

  


  

    
⚠️ Common Mistakes

    
    
      
  • Directly accessing nativeElement instead of using @HostBinding
    • 
      
  • Forgetting to add the directive to the component's imports array (standalone)
    • 
      
  • Not cleaning up event listeners added manually inside the directive
    • 
      
  • Naming the directive selector without a prefix, causing conflicts with native attributes
    • 
      
  • Confusing @HostListener('click') (directive host) with (click) (template)
    •
