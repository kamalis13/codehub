Module 5 — Directives

ngSwitch

Render one view from many alternatives — cleaner multi-case conditional rendering

📌 Definition

ngSwitch is a set of cooperating directives for rendering one template from multiple candidates based on a matching value. It consists of: [ngSwitch]="expression" (property binding on the container), *ngSwitchCase="value" (structural directive on each case), and *ngSwitchDefault (fallback when no case matches). Only the matching case is added to the DOM; all others are removed.

🤔 Why is it needed?

  • Cleanly handle 3+ mutually exclusive views without chaining multiple *ngIf directives
  • Only the matching view exists in the DOM — others are not rendered at all
  • Strongly communicates intent: "this block switches between these views"
  • Ideal for role-based UI (admin/user/guest views), status displays, tab panels
  • Works with components as cases — swap entire component trees cleanly

🌐 Real-time Example

    
An Order Status display that renders a different styled badge for each order status (pending, processing, shipped, delivered, cancelled) — a perfect real-world use case for ngSwitch over chained *ngIf.

    

  


  

    
⚙️ Internal Working

    
The [ngSwitch] directive sets an internal switch value on the container. Each *ngSwitchCase directive registers itself with the parent NgSwitch directive and provides its match value. When the switch value changes, NgSwitch iterates all registered cases, calls vcr.createEmbeddedView() for matching cases, and vcr.clear() for non-matching ones. *ngSwitchDefault renders when no case matches.

  


  

    

      
✅ Advantages

      
    
        
  • More readable than chaining multiple *ngIf conditions
    • 
        
  • Only renders the matching case — others are removed from DOM
    • 
        
  • Scales cleanly as the number of cases grows
    • 
        
  • Works with components as cases, not just simple elements
    • 
        
  • ng-container support avoids extra wrapper elements
    • 
      

    

    

      
❌ Disadvantages

      
    
        
  • Requires three separate directives — slightly more verbose than *ngIf
    • 
        
  • Does not support range comparisons (use *ngIf for value > 10)
    • 
        
  • All *ngSwitchCase directives must be direct children of the [ngSwitch] element
    • 
        
  • Cannot share one case template for multiple values (without ng-template tricks)
    • 
      

    

  


  

    
🏆 Best Practices

    
    
      
  • Use ng-container [ngSwitch] to avoid adding an unnecessary wrapper element
    • 
      
  • Always include *ngSwitchDefault as a fallback for unexpected values
    • 
      
  • Prefer ngSwitch over chained *ngIf when comparing the same variable to different values
    • 
      
  • Use TypeScript union types for the switch value to get compile-time safety
    • 
      
  • For 2 cases, prefer *ngIf; else — ngSwitch is overkill for binary conditions
    • 
    

  


  

    
⚠️ Common Mistakes

    
    
      
  • Putting [ngSwitch] on a child element instead of the parent container
    • 
      
  • Using *ngSwitch (structural) instead of [ngSwitch] (property binding) on the container
    • 
      
  • Forgetting *ngSwitchDefault — leaves the UI blank on unexpected values
    • 
      
  • Comparing objects with *ngSwitchCase — only reference equality works
    • 
      
  • Forgetting to import NgSwitch, NgSwitchCase, or CommonModule
    •
