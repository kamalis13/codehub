Module 5 — Directives

Structural Directive

Reshape the DOM — add, remove, or manipulate elements dynamically

📌 Definition

A Structural Directive changes the structure of the DOM by adding, removing, or rearranging elements. They use the * prefix (syntactic sugar for <ng-template> desugaring). Built-in structural directives include *ngIf, *ngFor, and *ngSwitch. Custom structural directives are built with TemplateRef and ViewContainerRef.

🤔 Why is it needed?

  • Conditionally include or exclude parts of the UI (*ngIf)
  • Render dynamic lists without manual DOM manipulation (*ngFor)
  • Switch between multiple views based on a value (*ngSwitch)
  • Create reusable DOM-manipulation abstractions (custom structural directives)
  • Avoid JavaScript DOM APIs — keep templates declarative and readable

⚙️ Internal Working

    
When Angular sees *ngIf="condition", it desugars it to <ng-template [ngIf]="condition">. The NgIf directive class receives a TemplateRef (the wrapped template) and ViewContainerRef (where to insert it). When the condition is true, it calls vcr.createEmbeddedView(templateRef) to insert the view into the DOM. When false, it calls vcr.clear() to remove it. This is the same mechanism for all structural directives including custom ones.

  


  

    

      
✅ Advantages

      
    
        
  • Declarative — DOM manipulation described in templates, not imperative code
    • 
        
  • *ngIf prevents rendering of hidden content, saving memory and CPU
    • 
        
  • *ngFor with trackBy enables efficient list re-rendering
    • 
        
  • Custom directives enable reusable DOM-manipulation patterns
    • 
        
  • Angular handles lifecycle (creation/destruction) automatically
    • 
      

    

    

      
❌ Disadvantages

      
    
        
  • *ngIf destroys and recreates components — initialization cost on toggle
    • 
        
  • Cannot apply two structural directives on the same element
    • 
        
  • *ngFor without trackBy causes full list re-rendering on any change
    • 
        
  • Custom structural directive API (TemplateRef/ViewContainerRef) is complex
    • 
      

    

  


  

    
🏆 Best Practices

    
    
      
  • Always use trackBy with *ngFor for large or frequently updated lists
    • 
      
  • Use <ng-container> to apply structural directives without adding wrapper DOM elements
    • 
      
  • Prefer *ngIf; else pattern over two separate *ngIf and *ngIf="!" blocks
    • 
      
  • Combine *ngIf with async pipe using ng-container for Observable data
    • 
      
  • Do not apply two structural directives to the same element — nest them instead
    • 
    

  


  

    
⚠️ Common Mistakes

    
    
      
  • Applying both *ngIf and *ngFor on the same element (runtime error)
    • 
      
  • Omitting trackBy in *ngFor, causing full list re-renders on every change
    • 
      
  • Using [hidden] when *ngIf is more appropriate for heavy components
    • 
      
  • Forgetting to import NgIf, NgFor, or CommonModule in standalone components
    • 
      
  • Writing custom structural directive but forgetting the @Input setter naming convention
    •
