Module 5 — Directives

ngIf

Conditionally include or completely remove elements from the DOM

📌 Definition

*ngIf is a built-in structural directive that conditionally adds or removes an element (and its subtree) from the DOM based on a boolean expression. When the condition is false, the element is completely destroyed — not just hidden. When true, it is recreated. It supports an else template and works seamlessly with the async pipe for Observable data.

🤔 Why is it needed?

  • Show/hide content based on application state (auth, loading, errors)
  • Completely remove heavy components from the DOM to free memory
  • Provide else-template for alternate views (login vs. dashboard)
  • Works with the async pipe to safely render Observable data only when available
  • Stops change detection for the hidden subtree, improving performance

⚙️ Internal Working

    
*ngIf="condition" desugars to <ng-template [ngIf]="condition">. The NgIf directive receives the TemplateRef and ViewContainerRef via DI. When the input changes, it evaluates the condition and either calls vcr.createEmbeddedView(templateRef) (to render) or vcr.clear() (to destroy). For the else template, it holds a second TemplateRef and renders it when the condition is falsy.

  


  

    

      
✅ Advantages

      
    
        
  • Removes element from DOM — saves memory and stops change detection
    • 
        
  • Triggers ngOnDestroy on hidden components — prevents memory leaks
    • 
        
  • Elegant else/then template syntax
    • 
        
  • Works naturally with the async pipe for Observable-driven UIs
    • 
        
  • Desugars to standard ng-template — transparent and debuggable
    • 
      

    

    

      
❌ Disadvantages

      
    
        
  • Recreates component on each toggle — initialization overhead
    • 
        
  • Not ideal for frequently toggled heavy components (consider [hidden])
    • 
        
  • Loses component state on each destroy/recreate cycle
    • 
        
  • Cannot be combined with *ngFor on the same element
    • 
      

    

  


  

    
🏆 Best Practices

    
    
      
  • Use the *ngIf; else pattern instead of two opposing *ngIf directives
    • 
      
  • Combine with ng-container to avoid extra DOM elements
    • 
      
  • Use *ngIf="obs$ | async as data" to unwrap Observable data safely
    • 
      
  • For frequently toggled lightweight elements, consider [hidden] instead
    • 
      
  • Keep the condition expression simple — move complex logic to a component property
    • 
    

  


  

    
⚠️ Common Mistakes

    
    
      
  • Applying *ngIf and *ngFor on the same element — use ng-container
    • 
      
  • Expecting the component to retain state after *ngIf toggles to false
    • 
      
  • Using *ngIf="!loading && !error" instead of the cleaner else-template pattern
    • 
      
  • Forgetting to import NgIf or CommonModule in standalone components
    • 
      
  • Using [hidden] for heavy components — they stay in DOM consuming resources
    •
