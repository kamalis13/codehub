Module 5 — Directives

ngFor

Render lists — iterate over any collection and stamp out DOM for each item

📌 Definition

*ngFor is a built-in structural directive that renders a template for each item in an iterable (array, Set, etc.). It uses the NgFor micro-syntax and exposes powerful local variables: index, first, last, even, odd, and count. For performance, always use trackBy to give Angular a way to identify items and avoid unnecessary DOM re-creation.

🤔 Why is it needed?

  • Declaratively render dynamic lists without manual DOM manipulation
  • Access contextual variables (index, first, last) for conditional styling
  • Minimize DOM re-renders with trackBy for large, updating lists
  • Supports nested iteration for hierarchical data (categories and items)
  • Works with any JavaScript iterable — arrays, Sets, sliced arrays

⚙️ Internal Working

    
Angular desugars *ngFor into <ng-template ngFor [ngForOf]="items" [ngForTrackBy]="trackFn">. The NgFor directive class maintains a list of EmbeddedViewRef objects — one per item. On each change detection cycle, it compares current items against the tracked keys, computes a diff, then inserts new views, removes stale views, and updates changed views in-place. The trackBy function is the key used in this diff algorithm.

  


  

    

      
✅ Advantages

      
    
        
  • Declarative list rendering — no manual DOM or array manipulation
    • 
        
  • Built-in local variables (index, first, last, even, odd) for rich UI logic
    • 
        
  • trackBy drastically reduces DOM operations on list updates
    • 
        
  • Supports nested iteration for hierarchical data structures
    • 
        
  • Participates in Angular's change detection automatically
    • 
      

    

    

      
❌ Disadvantages

      
    
        
  • Without trackBy, every change triggers full list re-render
    • 
        
  • Deeply nested *ngFor loops can degrade performance (O(n*m) complexity)
    • 
        
  • Does not natively support pagination — requires manual slicing
    • 
        
  • Cannot iterate directly over plain Objects (use keyvalue pipe)
    • 
      

    

  


  

    
🏆 Best Practices

    
    
      
  • Always use trackBy for lists that update dynamically (API data, user actions)
    • 
      
  • Define the trackBy function in the component class (not as an arrow in template)
    • 
      
  • Use <ng-container *ngFor> to avoid extra DOM wrapper elements
    • 
      
  • Combine *ngFor with the slice pipe for client-side pagination
    • 
      
  • For large lists (1000+ items), consider virtual scrolling (CDK VirtualScrollViewport)
    • 
    

  


  

    
⚠️ Common Mistakes

    
    
      
  • Omitting trackBy — causes full DOM re-renders on every list update
    • 
      
  • Applying *ngFor and *ngIf on the same element — wrap with ng-container
    • 
      
  • Mutating array items in-place when using OnPush — Angular won't detect the change
    • 
      
  • Using object reference as trackBy key — objects change identity on every API call
    • 
      
  • Forgetting to import NgFor or CommonModule in standalone components
    •
