Module 5 — Directives

ngClass

Dynamically add and remove CSS classes based on component state

📌 Definition

[ngClass] is a built-in attribute directive that dynamically adds or removes CSS classes on a DOM element. It merges with any static class attribute already on the element. It accepts three forms: a string (space-separated class names), an array of class names, or an object where keys are class names and values are booleans that control whether the class is applied.

🤔 Why is it needed?

  • Dynamically apply validation state classes (valid, invalid, warning, pristine)
  • Toggle active/inactive state on navigation items and tab buttons
  • Conditionally apply multiple classes from one clean binding
  • React to user interaction (focus, hover, selection) with CSS class changes
  • Keeps class logic in TypeScript where it can be unit-tested

⚙️ Internal Working

    
Angular's NgClass directive subscribes to the bound expression. During change detection, it evaluates the expression (string/array/object) and computes the set of classes to add and remove. It uses a differ internally to track which classes changed since the last cycle, then calls renderer.addClass() and renderer.removeClass() only for changed classes — this minimizes actual DOM mutations.

  


  

    

      
✅ Advantages

      
    
        
  • Multiple class conditions in a single clean binding
    • 
        
  • Merges safely with static class attributes
    • 
        
  • Separates class logic from HTML — testable in the component
    • 
        
  • Object syntax reads like documentation — what class, when it applies
    • 
        
  • Supports computed getters for complex class logic
    • 
      

    

    

      
❌ Disadvantages

      
    
        
  • Object literal in template creates new reference each cycle (use getter instead)
    • 
        
  • Verbose for toggling a single class (use [class.name] instead)
    • 
        
  • Complex class logic in template reduces readability
    • 
        
  • Debugging active classes requires Angular DevTools or manual inspection
    • 
      

    

  


  

    
🏆 Best Practices

    
    
      
  • Use a getter in the component class to return the class object — avoids new object creation in template
    • 
      
  • Use [class.name]="expr" for toggling a single class
    • 
      
  • Keep class object keys consistent with your CSS naming convention (BEM, utility-first, etc.)
    • 
      
  • Prefer [ngClass] over string concatenation in class attributes
    • 
      
  • Use TypeScript's computed properties for dynamic key names in class objects
    • 
    

  


  

    
⚠️ Common Mistakes

    
    
      
  • Using an inline object literal [ngClass]="{ ... }" — creates a new object every CD cycle
    • 
      
  • Thinking [ngClass] replaces static classes — it does not, it merges
    • 
      
  • Using [class]="str" instead of [ngClass] — [class] replaces all classes
    • 
      
  • Forgetting to import NgClass or CommonModule in standalone components
    • 
      
  • Putting too much conditional logic inside the template instead of using a computed getter
    •
