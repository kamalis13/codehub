Module 10 — HTTP

HTTP GET

Fetch data from APIs — typed, cancellable, and reactive

📌 Definition

http.get<T>(url, options) sends an HTTP GET request and returns a cold Observable that emits the response body typed as T. Nothing is sent until subscribed. It is the most common HTTP method used in Angular applications for data retrieval.

🤔 Why is it needed?

  • Loading lists, detail views, search results, and paginated data from a REST API
  • Integrates with the async pipe for automatic subscription lifecycle management
  • Supports query parameters via HttpParams for filtering, sorting, and pagination
  • Full response access via observe: 'response' exposes status codes and custom headers

🌐 Real-time Example

    
A product catalogue page uses HttpClient GET to load products by category and page number, passes query parameters via HttpParams, and uses the async pipe so subscriptions are managed automatically. Errors are caught and the stream is completed silently with EMPTY.

    

  


  

    
⚙️ Internal Working

    
When you call http.get(), Angular creates a cold Observable. On subscription, the request enters Angular's HttpHandler pipeline, passing through all registered interceptors in registration order. The final handler dispatches an XMLHttpRequest to the network. On response, the raw bytes are parsed as JSON (by default), typed as T, and emitted to the subscriber. Cancellation via unsubscribe sends an XHR abort before the response completes.

  


  

    

      
✅ Advantages

      
    
        
  • Typed generics give compile-time safety over the response shape
    • 
        
  • Cancellable via unsubscribe — prevents stale responses in fast navigation
    • 
        
  • HttpParams builder ensures correct URL encoding without manual string concatenation
    • 
      

    

    

      
❌ Disadvantages

      
    
        
  • No built-in caching — repeated calls hit the network unless you add shareReplay or an interceptor
    • 
        
  • Generic type is a compile-time cast only — a mismatched server response will not throw at runtime
    • 
      

    

  


  

    
🏆 Best Practices

    
    
      
  • Always provide a generic type: http.get<Product[]>(url) for type safety
    • 
      
  • Use the async pipe in templates to avoid memory leaks from unmanaged subscriptions
    • 
      
  • Add catchError in the service layer to handle errors before they reach the component
    • 
    

  


  

    
⚠️ Common Mistakes

    
    
      
  • Using mutable string concatenation for query params instead of HttpParams, causing incorrect URL encoding
    • 
      
  • Subscribing inside a service method and returning the value synchronously — always return the Observable
    •
