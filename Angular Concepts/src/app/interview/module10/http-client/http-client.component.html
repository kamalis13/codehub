Module 10 — HTTP

HttpClient

Angular's built-in HTTP service — type-safe, Observable-based API communication

📌 Definition

HttpClient is Angular's primary service for making HTTP requests. It is provided by @angular/common/http and returns RxJS Observables for all requests — meaning requests are lazy and nothing is sent until you subscribe.

🤔 Why is it needed?

  • Enables typed HTTP communication with full TypeScript generic support
  • Provides automatic JSON serialisation and deserialisation out of the box
  • Supports interceptors for cross-cutting concerns like authentication, logging, and caching
  • Observable API integrates perfectly with Angular's reactive architecture and the async pipe

⚙️ Internal Working

    
HttpClient wraps the browser's XMLHttpRequest (or fetch in newer Angular). Each method call creates a cold Observable — no network activity occurs until subscription. When subscribed, Angular's HttpHandler pipeline passes the request through all registered interceptors in order before dispatching it to the backend. The response travels back through the same interceptor chain in reverse before reaching the subscriber.

  


  

    

      
✅ Advantages

      
    
        
  • Type-safe responses via TypeScript generics reduce runtime errors
    • 
        
  • Cold Observables are cancellable — unsubscribing aborts the in-flight request
    • 
        
  • Interceptor pipeline enables clean separation of concerns such as auth and logging
    • 
      

    

    

      
❌ Disadvantages

      
    
        
  • Generic typing is a compile-time cast only — shape is not validated at runtime
    • 
        
  • Forgetting to subscribe (or use the async pipe) means no request is ever sent
    • 
      

    

  


  

    
🏆 Best Practices

    
    
      
  • Always type responses with generics: http.get<Product[]>(url)
    • 
      
  • Prefer the async pipe over manual subscribe to avoid memory leaks
    • 
      
  • Register interceptors with provideHttpClient(withInterceptors([...])) for a tree-shakable, functional setup
    • 
    

  


  

    
⚠️ Common Mistakes

    
    
      
  • Calling http.get() without subscribing and wondering why no data arrives
    • 
      
  • Manually subscribing without unsubscribing, causing memory leaks in long-lived components
    •
