Module 10 — HTTP

HTTP POST

Send data to create new resources — the foundation of form submission

📌 Definition

http.post<T>(url, body, options) sends an HTTP POST request with a request body. Angular automatically serialises JavaScript objects to JSON and sets Content-Type: application/json. Returns an Observable of the server's response typed as T.

🤔 Why is it needed?

  • Creating new resources on the server such as users, orders, and posts
  • Submitting form data to a REST API in a structured, typed way
  • Sending data that is too large or sensitive to include in query parameters
  • Triggering server-side operations like sending emails or processing payments

🌐 Real-time Example

    
A user registration flow calls a POST endpoint with the form data as a typed DTO. The component sets a loading flag before subscribing and clears it on completion or error. An order creation service uses an auth header and applies optimistic UI updates via tap, rolling back on failure inside catchError.

    

  


  

    
⚙️ Internal Working

    
When http.post() is subscribed to, Angular serialises the body object to a JSON string and sets Content-Type automatically. The request passes through the interceptor chain, is dispatched via XMLHttpRequest, and the raw response bytes are parsed. The Observable emits the typed body (or the full HttpResponse when observe: 'response' is set) and then completes, making it safe to subscribe without explicit cleanup.

  


  

    

      
✅ Advantages

      
    
        
  • Automatic JSON serialisation and Content-Type header — no manual setup required
    • 
        
  • Typed request and response interfaces provide full compile-time safety
    • 
        
  • Observable-based — easily composable with operators like catchError, retry, and tap
    • 
      

    

    

      
❌ Disadvantages

      
    
        
  • Not idempotent — retrying on network failure can create duplicate resources without server-side deduplication
    • 
        
  • Body serialisation to JSON loses non-serialisable values such as functions, undefined, and circular references
    • 
      

    

  


  

    
🏆 Best Practices

    
    
      
  • Define typed DTOs for both the request body and the response to catch contract mismatches at compile time
    • 
      
  • Use an HTTP interceptor to attach auth tokens instead of adding headers manually in each service method
    • 
      
  • Always handle errors with catchError and inform the user — never silently swallow POST failures
    • 
    

  


  

    
⚠️ Common Mistakes

    
    
      
  • Manually setting Content-Type: application/json when Angular already does it — this is redundant and can conflict with multipart form submissions
    • 
      
  • Forgetting to handle the error callback in subscribe, causing uncaught errors when the server returns 4xx or 5xx responses
    •
