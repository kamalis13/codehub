Module 10 — HTTP

HTTP PATCH

Partial update — send only the fields that changed

📌 Definition

http.patch<T>(url, partialBody) sends an HTTP PATCH request with only the fields that need updating. Unlike PUT (which replaces the entire resource), PATCH merges the provided fields into the existing resource, leaving unspecified fields completely unchanged.

🤔 Why is it needed?

  • Efficient updates — send less data over the wire by sending only changed fields
  • Toggling boolean flags (isActive, isPublished) without sending the full object
  • Updating a single field or handling status transitions without fetching and resending the whole resource

🌐 Real-time Example

    

      Three common PATCH patterns: updating only the email field, toggling a product's active status,
      and collecting dirty form controls to send only the fields the user actually changed.
    

    

  


  

    
⚙️ Internal Working

    

      The client sends a PATCH request with a partial JSON body. The server loads the existing resource
      from its data store, merges only the received fields into the stored object (leaving all other fields
      untouched), validates the merged result, and persists it. The server typically returns the full
      updated resource. Unlike PUT, PATCH does not require the client to know or send the entire resource.
    

  


  

    

      
✅ Advantages

      
    
        
  • Minimal payload — only send what changed, reducing bandwidth and processing
    • 
        
  • Safe for partial knowledge — client does not need to know all resource fields
    • 
        
  • Ideal for single-field updates, toggles, and status transitions
    • 
      

    

    

      
❌ Disadvantages

      
    
        
  • Not guaranteed to be idempotent — repeated identical PATCH calls may have different results
    • 
        
  • Server implementation complexity — must carefully merge only provided fields without clobbering others
    • 
      

    

  


  

    
🏆 Best Practices

    
    
      
  • Use TypeScript's Partial<T> type for the PATCH body to enforce type safety on partial objects
    • 
      
  • Check form control dirty state before sending to avoid no-op PATCH requests
    • 
      
  • Document your API's PATCH semantics clearly — specify which fields are patchable and which are immutable
    • 
    

  


  

    
⚠️ Common Mistakes

    
    
      
  • Sending an empty object in a PATCH — always guard with a dirty-fields check before calling http.patch()
    • 
      
  • Assuming PATCH is idempotent — design and test for non-idempotent cases such as append or increment operations
