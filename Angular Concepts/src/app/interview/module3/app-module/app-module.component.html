Module 3 — Modules

AppModule

The root NgModule that bootstraps and wires up the entire Angular application

📌 Definition

AppModule is the root NgModule in every classic Angular application. Decorated with @NgModule, it tells Angular which components, directives, and pipes belong to the application, which external modules to import, which services to provide globally, and which component to bootstrap into index.html. Angular reads AppModule at startup to construct the full module factory and dependency-injection tree before rendering anything on screen.

🤔 Why is it needed?

  • Acts as the single entry point Angular uses to bootstrap the browser application.
  • Centralises global configuration — routing, HTTP, animations — so every feature module inherits them automatically.
  • Registers app-wide singleton providers (e.g., AuthService, HTTP interceptors) once in the root injector.
  • Declares which components are available for compilation before the app is served.
  • Defines the bootstrap component that Angular inserts into <app-root> in index.html.

🌐 Real-time Example

    

      In an e-commerce app, AppModule imports BrowserModule for browser APIs,
      AppRoutingModule to handle navigation between pages (Home, Products, Cart, Checkout),
      and HttpClientModule to enable REST calls. An HTTP_INTERCEPTORS token is
      registered here so every HTTP request automatically attaches a JWT token — no feature module needs to know about it.
    

    

  


  

    
⚙️ Internal Working

    

      When main.ts calls platformBrowserDynamic().bootstrapModule(AppModule), Angular's
      JIT compiler (or AOT pre-compiled factory) reads the @NgModule metadata. It builds a
      module factory — a compiled representation of all declared, imported, and exported tokens —
      and creates a root NgModuleRef. This ref holds the root injector populated with all providers.
      Angular then instantiates the bootstrap component, attaches it to the DOM, and starts the
      change-detection zone, completing the startup sequence.
    

  


  

    

      
✅ Advantages

      
    
        
  • Single, well-known place for global configuration and DI registration.
    • 
        
  • Familiar pattern understood by all Angular developers pre-Angular 14.
    • 
        
  • Integrates cleanly with lazy-loaded feature modules via the router.
    • 
        
  • Allows fine-grained control over what is available application-wide vs. feature-scoped.
    • 
      

    

    

      
❌ Disadvantages

      
    
        
  • Can become a "god module" if too many declarations and providers are added directly.
    • 
        
  • Adds boilerplate — every component must be declared in some module.
    • 
        
  • Module resolution errors (e.g., "not a known element") can be cryptic.
    • 
        
  • Deprecated in favour of standalone components in Angular 17+ projects.
    • 
      

    

  


  

    
🏆 Best Practices

    
    
      
  • Keep AppModule lean — only global setup, no feature components declared directly.
    • 
      
  • Move features into dedicated feature modules and import them lazily via the router.
    • 
      
  • Import BrowserModule only here; use CommonModule in feature modules.
    • 
      
  • Register singleton services in CoreModule or use providedIn: 'root' instead of AppModule providers.
    • 
      
  • Use forRoot() pattern for modules that need one-time configuration (e.g., RouterModule.forRoot(routes)).
    • 
    

  


  

    
⚠️ Common Mistakes

    
    
      
  • Declaring every component directly in AppModule instead of feature modules — kills maintainability.
    • 
      
  • Importing BrowserModule in a feature module — causes a duplicate-provider runtime error.
    • 
      
  • Providing services in AppModule that should be lazy-scoped — they become singletons when they shouldn't be.
    • 
      
  • Forgetting to add a new component to declarations — leads to "is not a known element" errors.
    • 
      
  • Importing large third-party modules globally that are only needed in one feature — bloats the initial bundle.
    •
