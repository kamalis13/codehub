Interpolation

Bind TypeScript expressions to HTML using the double-curly-brace syntax

📌 Definition

Interpolation is Angular's simplest data-binding mechanism. Using double curly braces {{ expression }}, it evaluates a TypeScript expression from the component class and inserts the resulting string into the HTML. Angular's template compiler converts the expression into a DOM text node and registers a binding so the view automatically updates whenever the underlying data changes during change detection.

🤔 Why is it needed?

  • Dynamic content — display component data (names, prices, counts) in the HTML without manual DOM manipulation.
  • Reactive updates — Angular's change detection re-evaluates expressions and updates the DOM automatically.
  • Readable templates — keeps HTML declarative and close to natural language.
  • Pipe integration — combine with pipes for formatted output without extra logic in the component.
  • XSS safety — Angular HTML-encodes interpolated values, preventing script injection by default.

⚙️ Internal Working

    

      During AOT compilation, Angular transforms each {{ expr }} into an
      efficient JavaScript expression inside a generated view factory. At runtime, Angular's change detection
      evaluates the expression and compares its result with the previously stored value (dirty checking).
      If the value has changed, Angular updates the corresponding DOM text node. Expressions are evaluated
      in the component's execution context, with access to all public properties and methods of the
      component class.
    

  


  

    

      
✅ Advantages

      
    
        
  • Simplest and most readable data-binding syntax — no special attribute knowledge required.
    • 
        
  • Automatically sanitises output, protecting against XSS by default.
    • 
        
  • Works seamlessly with Angular pipes for formatting.
    • 
        
  • Reactive — the DOM updates automatically when data changes.
    • 
      

    

    

      
❌ Disadvantages

      
    
        
  • Always produces a string — cannot bind boolean or object values to DOM properties.
    • 
        
  • Cannot use statements, assignments, or certain JS operators (new, ++, --).
    • 
        
  • Complex inline expressions reduce readability and are hard to test.
    • 
        
  • Method calls in templates execute on every change detection cycle — avoid expensive computations.
    • 
      

    

  


  

    
🏆 Best Practices

    
    
      
  • Keep interpolated expressions simple — use component getters or methods for complex logic.
    • 
      
  • Use Angular pipes for formatting (date, currency, uppercase) instead of inline methods.
    • 
      
  • Avoid calling expensive methods in templates — cache results in component properties instead.
    • 
      
  • Use property binding [attr] when the target needs a non-string value (boolean, number, object).
    • 
      
  • Prefer {{ value | async }} with the async pipe for Observable values instead of subscribing manually.
    • 
    

  


  

    
⚠️ Common Mistakes

    
    
      
  • Using {{ }} inside a <pre> tag — causes template parse issues; use [innerText] instead.
    • 
      
  • Placing assignment expressions ({{ count = 0 }}) inside interpolation — this is not allowed in Angular templates.
    • 
      
  • Using interpolation for boolean DOM attributes (disabled="{{ isDisabled }}") — the string "false" still disables the element; use [disabled]="isDisabled".
    • 
      
  • Putting heavy computations directly in interpolation — they run on every change detection tick, harming performance.
    • 
      
  • Rendering raw HTML via interpolation expecting tags to render — Angular encodes them; use [innerHTML] with DomSanitizer for intentional HTML.
