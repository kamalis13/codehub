Dependency Injection

Angular's design pattern for managing dependencies

📌 Definition

Dependency Injection (DI) is Angular's built-in design pattern where components and services declare what they need, and Angular's injector provides the correct instances. Instead of creating dependencies with new, you request them — Angular handles creation, caching, and lifecycle.

🤔 Why is it needed?

  • Eliminates tight coupling between classes
  • Makes unit testing trivial (inject mocks instead of real services)
  • Angular manages object creation and lifecycle
  • Enables hierarchical scoping of service instances
  • Promotes the Open/Closed principle

🌐 Real-time Example

    
A shopping cart component injects AuthService (root singleton — shared) and CartService (component-level — scoped). Each cart component gets its own CartService while sharing the same AuthService.

    

  


  

    
⚙️ Internal Working

    
When Angular compiles a component, it reads its constructor parameter types. At runtime, the injector resolves each parameter by finding the nearest provider in the injector hierarchy. The resolved instance is injected before the constructor body executes. Angular 14+ inject() function works in injection contexts.

🏆 Best Practices

  • Use inject() in standalone/functional contexts

  • Use InjectionToken for non-class values
    • 
      
  • Apply @Optional for truly optional dependencies

  • Document when and why component-level providers are used
