Module 7 — Services

Angular Services

Reusable business logic and data access layer

📌 Definition

A service is a TypeScript class decorated with @Injectable that provides reusable business logic, data access, and shared state across components. Services embody the principle of separation of concerns — components handle presentation, services handle everything else.

🤔 Why is it needed?

  • Share logic across multiple components without duplication
  • Keep components lean and focused on UI rendering
  • Enable independent unit testing of business logic
  • Centralize HTTP calls and data transformations
  • Manage shared application state

🌐 Real-time Example

    
A UserService fetches users from an API. Any component that needs user data injects this service, avoiding duplicate HTTP calls and keeping components free of HTTP logic.

    

  


  

    
⚙️ Internal Working

    
Angular registers the service with an Injector at the specified level. When a component requests the service via its constructor, the Injector looks it up and injects the existing instance (or creates a new one if none exists). With providedIn: 'root', Angular registers it in the root injector at startup, ensuring a single instance shared across all components.

  


  

    

      
✅ Advantages

      
    
        
  • Promotes DRY — write logic once, reuse everywhere
    • 
        
  • Highly testable with Angular TestBed or plain jest mocks
    • 
        
  • Singleton by default — consistent shared state
    • 
        
  • Angular handles instantiation and lifecycle
    • 
      

    

    

      
❌ Disadvantages

      
    
        
  • Overloading a service with unrelated concerns (god service)
    • 
        
  • Shared mutable state can cause unexpected side effects
    • 
        
  • Debugging injection errors can be complex in large hierarchies
    • 
      

    

  


  

    
🏆 Best Practices

    
    
      
  • One service per concern (UserService, AuthService, ProductService)
    • 
      
  • Use providedIn: 'root' for app-wide services
    • 
      
  • Keep services stateless when possible
    • 
      
  • Use Observables (not Promises) for async operations
    • 
    

  


  

    
⚠️ Common Mistakes

    
    
      
  • Forgetting @Injectable on services that inject other services
    • 
      
  • Providing a service in both root and a component (creates duplicate instances)
    • 
      
  • Subscribing inside a service and not unsubscribing
    • 
      
  • Storing mutable arrays/objects directly — prefer immutable patterns
    •
