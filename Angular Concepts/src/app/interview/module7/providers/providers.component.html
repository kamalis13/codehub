Module 7 — Services

Providers

How Angular registers and creates service instances

📌 Definition

A provider is a configuration object that tells Angular's injector how to create or locate a value for a given token. Providers are the bridge between a DI token (what you ask for) and its implementation (what you get). They can map tokens to classes, values, factories, or aliases.

🤔 Why is it needed?

  • Decouple the token (interface/class) from the concrete implementation
  • Enable environment-specific configurations (dev vs prod)
  • Allow injection of non-class values like strings, numbers, configs
  • Support aliasing and backward-compatible API evolution
  • Enable fine-grained control over service scope and lifetime

🌐 Real-time Example

    
An API_URL InjectionToken lets the app switch between development and production endpoints without changing service code. The LoggerService swaps between verbose and silent implementations based on environment.

    

  


  

    
⚙️ Internal Working

    
When Angular bootstraps, it reads all provider configurations and populates the injector's registry. When a dependency is requested, the injector looks up its token in the registry and executes the provider recipe: new ClassName() for useClass, the literal for useValue, factory function result for useFactory, or redirects to another token for useExisting.

❌ Disadvantages

      
    
        
  • useFactory with many deps can become verbose
    • 
        
  • Mistyped token references fail silently until runtime
    • 
        
  • Understanding when to use each type requires experience
    • 
        
  • Multi-providers (multi: true) can be surprising
    • 
      

    

  


  

    
🏆 Best Practices

    
    
      
  • Use InjectionToken for all non-class values
    • 
      
  • Prefer providedIn over NgModule providers for tree-shaking
    • 
      
  • Use useClass to swap implementations for testing
    • 
      
  • Keep factory functions pure and testable
    • 
      
  • Document each custom provider with a comment
    • 
    

  


  

    
⚠️ Common Mistakes

    
    
      
  • Forgetting deps array in useFactory (services won't be injected)
    • 
      
  • Using string tokens instead of InjectionToken (collision risk)
    • 
      
  • Providing the same service in both root and a module (dual instances)
    • 
      
  • Not using multi: true for HTTP_INTERCEPTORS
