Module 8 — Routing

Child Routes

Building hierarchical navigation with nested router-outlet

📌 Definition

Child routes are route configurations nested inside a parent route using the children property. The parent component acts as a layout shell containing shared UI (sidebar, header, tabs) and a router-outlet where child components render. This creates hierarchical navigation that reflects the structure of complex UIs.

🤔 Why is it needed?

  • Build admin dashboards with persistent sidebar + changing content area
  • Create tabbed interfaces where each tab is a separate routable view
  • Implement wizards where each step has its own URL
  • Organize routes to mirror the UI hierarchy
  • Enable relative navigation between related views

⚙️ Internal Working

    
When Angular navigates to a child route like /admin/users, it first renders the parent component (AdminLayoutComponent) in the root router-outlet. It then looks for a second router-outlet inside AdminLayoutComponent's template and renders the child component (UserListComponent) there. Parent route's guards and resolvers run first, then child's. The parent component's lifecycle hooks are not re-run when only the child changes.

  


  

    

      
✅ Advantages

      
    
        
  • Persistent layout UI (sidebar, header) across child navigation
    • 
        
  • Organized route hierarchy mirrors UI structure
    • 
        
  • Parent-level guards protect all children at once
    • 
        
  • Relative navigation within child routes is clean
    • 
        
  • Shared resolvers can provide data to all children
    • 
      

    

    

      
❌ Disadvantages

      
    
        
  • Each nesting level requires a router-outlet in the parent
    • 
        
  • Accessing parent route params from children adds complexity
    • 
        
  • Very deep nesting is hard to debug
    • 
        
  • Route configuration becomes verbose for many nested levels
    • 
      

    

  


  

    
🏆 Best Practices

    
    
      
  • Keep nesting depth to 2-3 levels maximum
    • 
      
  • Use parent route for layout, children for content
    • 
      
  • Add canActivate on the parent to protect all children at once
    • 
      
  • Use redirectTo with pathMatch: 'full' for default child routes
    • 
      
  • Access parent params via this.route.parent.paramMap
    • 
    

  


  

    
⚠️ Common Mistakes

    
    
      
  • Forgetting router-outlet in the parent template (child renders nowhere)
    • 
      
  • Using absolute paths in child route templates (breaking relative navigation)
    • 
      
  • Not setting a default child route (empty sub-path with redirectTo)
    • 
      
  • Duplicating guards on each child when parent-level guard suffices
    •
