Module 8 — Routing

Route Configuration

Mapping URL paths to components with a declarative Routes array

📌 Definition

Route configuration is the Routes array that serves as Angular's routing table — a declarative map between URL paths and the components, modules, or redirects they should activate. Each entry in the array is a Route object with properties like path, component, loadChildren, canActivate, and data.

🤔 Why is it needed?

  • Define which component renders for each URL path
  • Support dynamic segments (:id), wildcards (**), and redirects
  • Attach route guards, resolvers, and metadata declaratively
  • Enable lazy loading of entire feature sets
  • Set document titles automatically per route

⚙️ Internal Working

    
Angular's Router reads the Routes array once at startup. On each navigation, it runs a matching algorithm from top to bottom — first exact matches, then prefix matches. The matched route's component is instantiated and rendered inside router-outlet. If loadChildren is specified, Angular dynamically imports the module/routes file. Guards execute before rendering; resolvers fetch data before rendering.

  


  

    

      
✅ Advantages

      
    
        
  • Fully declarative — easy to read and maintain
    • 
        
  • Type-safe (Routes type in TypeScript)
    • 
        
  • Supports nested, lazy, and guarded routes in one config
    • 
        
  • route title property improves SEO automatically
    • 
        
  • Wildcard catch-all prevents blank pages
    • 
      

    

    

      
❌ Disadvantages

      
    
        
  • Large apps can have sprawling route tables
    • 
        
  • Order dependency is a source of bugs (wildcard misplaced)
    • 
        
  • redirectTo + pathMatch rules confuse beginners
    • 
        
  • Dynamic route generation at runtime is not supported
    • 
      

    

  


  

    
🏆 Best Practices

    
    
      
  • Keep routes in app.routes.ts, not inline in AppModule
    • 
      
  • Always place ** last
    • 
      
  • Use pathMatch: 'full' on empty-path redirects
    • 
      
  • Add title to every route for accessibility/SEO
    • 
      
  • Group feature routes in their own routes files
    • 
    

  


  

    
⚠️ Common Mistakes

    
    
      
  • Placing ** before specific routes (blocks all other routes)
    • 
      
  • Omitting pathMatch: 'full' on empty path redirect (redirects everything)
    • 
      
  • Mixing component and loadChildren on same route
    • 
      
  • Forgetting canActivate on protected routes
    •
