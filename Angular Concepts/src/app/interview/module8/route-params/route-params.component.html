Module 8 — Routing

Route Parameters

Embedding dynamic values directly in the URL path (/products/:id)

📌 Definition

Route parameters are named URL segments prefixed with : that carry dynamic values as part of the path. They are defined in the route table as :paramName and extracted in the component via ActivatedRoute. They are ideal for identifying specific resources — /products/42, /users/john, /orders/ORD-789.

🤔 Why is it needed?

  • Identify specific resources in the URL (/products/:id)
  • Enable bookmarkable, shareable deep links to exact records
  • Support server-side rendering and SEO with meaningful URLs
  • Allow navigation to related resources without extra state
  • Trigger component data loading based on the URL

⚙️ Internal Working

    
Angular's route matching algorithm extracts the :paramName segments from the actual URL and populates the ActivatedRoute's paramMap and params. The component can read them via snapshot (current value only) or subscribe to paramMap$ (stream of changes). When navigating between the same route with different params, Angular can reuse the component instance and the Observable emits the new value.

  


  

    

      
✅ Advantages

      
    
        
  • Clean, semantic URLs that reflect resource identity
    • 
        
  • Fully shareable and bookmarkable
    • 
        
  • Works with browser back/forward navigation
    • 
        
  • paramMap observable handles in-place navigation elegantly
    • 
        
  • withComponentInputBinding simplifies param consumption
    • 
      

    

    

      
❌ Disadvantages

      
    
        
  • snapshot approach misses param changes on reuse
    • 
        
  • Multiple params in deep paths can get verbose
    • 
        
  • Must URL-encode special characters in param values
    • 
        
  • No optional path params — use query params instead
    • 
      

    

  


  

    
🏆 Best Practices

    
    
      
  • Use paramMap observable for components that can be navigated to with different param values
    • 
      
  • Use snapshot only for components that are always freshly created
    • 
      
  • Validate and sanitize param values before using in API calls
    • 
      
  • Use router.navigate(['/route', id]) instead of string concatenation
    • 
    

  


  

    
⚠️ Common Mistakes

    
    
      
  • Using snapshot when the component reuses on same-route navigation (stale data)
    • 
      
  • Forgetting to unsubscribe from paramMap$ (memory leak)
    • 
      
  • Relying on route params for optional filters instead of query params
    • 
      
  • Not handling the case where paramMap.get() returns null
    •
