Module 8 — Routing

Wildcard Routes

Catching all unmatched URLs with ** to show a custom 404 page

📌 Definition

The wildcard route uses the special path ** to match any URL that has not been matched by any prior route in the Routes array. It acts as a catch-all for unknown or mistyped URLs, typically rendering a 404 Not Found page. It is always the final entry in the route table.

🤔 Why is it needed?

  • Prevent blank white screens when users mistype URLs
  • Provide a friendly 404 page that helps users navigate back
  • Catch stale bookmarks and old links gracefully
  • Enable custom error messaging with context about what failed
  • Redirect legacy URLs to new paths with redirectTo

💻 Syntax


  


  

    
🌐 Real-time Example

    
A PageNotFoundComponent that reads the attempted URL from the Router service and displays it alongside a friendly message and a link back to home.

    

  


  

    
⚙️ Internal Working

    
Angular's route matching algorithm tries each route from top to bottom. When no path matches the current URL, ** matches as a fallback. The PageNotFoundComponent (or redirect target) is then rendered in the root router-outlet. The ** path uses prefix matching against the full remaining URL, so it catches everything including paths with multiple segments like /foo/bar/baz.

  


  

    

      
✅ Advantages

      
    
        
  • Prevents blank app renders for unknown URLs
    • 
        
  • Fully customizable 404 page with branding and navigation
    • 
        
  • Can redirect rather than show error (graceful fallback)
    • 
        
  • Works inside child route arrays for section-specific 404s
    • 
        
  • Simple to configure — one line
    • 
      

    

    

      
❌ Disadvantages

      
    
        
  • Misplacing it (not last) breaks all other routes
    • 
        
  • Can mask route configuration errors if used too broadly
    • 
        
  • redirectTo ** loses the context of what URL failed
    • 
        
  • Server must also return index.html for all paths or server-side 404 fires first
    • 
      

    

  


  

    
🏆 Best Practices

    
    
      
  • Always place ** last in the Routes array
    • 
      
  • Show the failed URL in the 404 component for clarity
    • 
      
  • Include navigation links back to home/dashboard
    • 
      
  • Log 404 events to your analytics service
    • 
      
  • Configure your web server (Nginx, Apache, Firebase) to serve index.html for all routes
    • 
    

  


  

    
⚠️ Common Mistakes

    
    
      
  • Placing ** before other routes (all routes become 404)
    • 
      
  • Using ** with redirectTo: '**' (infinite redirect loop)
    • 
      
  • Not configuring the server to serve index.html (server returns real 404 before Angular loads)
    • 
      
  • Omitting the wildcard entirely (blank screen for unknown URLs)
    •
