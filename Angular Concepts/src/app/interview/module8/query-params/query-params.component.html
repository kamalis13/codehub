Module 8 — Routing

Query Parameters

Passing optional, filterable data via URL query strings

📌 Definition

Query parameters are optional key-value pairs appended to the URL after a ? character (e.g., /products?search=angular&page=2&sort=price). Unlike route params, they do not affect route matching. They are ideal for search terms, pagination, sorting, and filters that users may want to bookmark or share.

🤔 Why is it needed?

  • Represent optional view state that should survive page refresh
  • Enable shareable/bookmarkable search and filter states
  • Pass data between routes without router state (which doesn't survive refresh)
  • Support pagination and sorting without new routes
  • Allow multiple optional parameters without path complexity

⚙️ Internal Working

    
Angular's Router parses query strings from the URL and makes them available through ActivatedRoute as queryParams (plain object) and queryParamMap (ParamMap interface). When you navigate with queryParams, the Router appends them to the URL. The queryParamMap$ observable emits every time the query string changes, enabling reactive filter updates without component re-creation.

  


  

    

      
✅ Advantages

      
    
        
  • Shareable, bookmarkable filter and search states
    • 
        
  • Multiple optional values without path complexity
    • 
        
  • No route matching involvement — add/remove freely
    • 
        
  • queryParamsHandling: 'merge' preserves other params
    • 
        
  • Multi-value params supported via getAll()
    • 
      

    

    

      
❌ Disadvantages

      
    
        
  • Sensitive data should never appear in query params (visible in browser history)
    • 
        
  • Long query strings reduce URL readability
    • 
        
  • All values are strings — parsing to numbers/booleans is manual
    • 
        
  • Syncing complex state to query params requires careful management
    • 
      

    

  


  

    
🏆 Best Practices

    
    
      
  • Use query params for search, filter, sort, and pagination state
    • 
      
  • Always parse numeric/boolean params explicitly (Number(), === 'true')
    • 
      
  • Use queryParamsHandling: 'merge' to preserve unrelated params
    • 
      
  • Read params from queryParamMap$ on init to restore state from URL
    • 
      
  • Never put sensitive data (tokens, passwords) in query params
    • 
    

  


  

    
⚠️ Common Mistakes

    
    
      
  • Using route params when query params are more appropriate (optional filters)
    • 
      
  • Forgetting queryParamsHandling: 'merge' and wiping existing params
    • 
      
  • Not handling null from paramMap.get() (crashes on first load)
    • 
      
  • Storing sensitive information in query params (visible in browser history and logs)
    •
