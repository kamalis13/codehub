Module 8 — Routing

Route Guards

Intercepting navigation to enforce authentication and permissions

📌 Definition

Route guards are functions (or classes) that Angular invokes before activating, deactivating, or loading a route. They return true (allow), false (block), or a UrlTree (redirect). Guards implement access control, unsaved-changes warnings, and data prefetching at the routing layer — before any component is rendered.

🤔 Why is it needed?

  • Prevent unauthorized access to protected pages (dashboard, admin)
  • Warn users before leaving a page with unsaved form data
  • Prefetch required data before rendering (avoid loading spinners)
  • Block lazy bundle downloads for unauthorized routes
  • Centralize access-control logic outside of components

⚙️ Internal Working

    
Angular's navigation pipeline runs guards in a defined sequence: canMatch → canActivate → canActivateChild → resolve → (render component). If any guard returns false or a UrlTree, Angular stops the pipeline and either blocks or redirects. Guards can return synchronous values, Promises, or Observables — Angular waits for async guards to resolve before proceeding.

  


  

    

      
✅ Advantages

      
    
        
  • Centralized access control — not scattered across components
    • 
        
  • Component is never rendered for unauthorized users
    • 
        
  • canDeactivate prevents accidental data loss
    • 
        
  • resolve ensures components have data before rendering
    • 
        
  • Functional guards are simple and tree-shakable
    • 
      

    

    

      
❌ Disadvantages

      
    
        
  • canActivate does not prevent lazy bundle download (use canMatch for that)
    • 
        
  • Complex guard chains are hard to debug
    • 
        
  • Async guards that error crash silently without error handling
    • 
        
  • Over-using resolve guards can slow navigation if the fetch is slow
    • 
      

    

  


  

    
🏆 Best Practices

    
    
      
  • Use functional guards (inject()-based) in Angular 14+ projects
    • 
      
  • Return UrlTree for redirects, not router.navigate() (causes double navigation)
    • 
      
  • Use canMatch on lazy routes for unauthorized users
    • 
      
  • Keep guard logic thin — delegate to AuthService/PermissionService
    • 
      
  • Handle observable errors in guards with catchError
    • 
    

  


  

    
⚠️ Common Mistakes

    
    
      
  • Returning undefined instead of true/false from a guard
    • 
      
  • Using canActivate on lazy routes when canMatch is needed
    • 
      
  • Using router.navigate() inside a guard instead of returning UrlTree
    • 
      
  • Not passing returnUrl queryParam when redirecting to login
    • 
      
  • Forgetting to provide class-based guards in the module
    •
