Module 1 — Angular Fundamentals

What is Angular?

A TypeScript-based platform and framework by Google for building scalable single-page applications.

📌 Definition

Angular is a TypeScript-based open-source web application framework developed and maintained by Google. It is a complete platform — not just a rendering library — that provides everything needed to build modern, scalable single-page applications (SPAs): a powerful CLI, built-in routing, reactive forms, HTTP client, dependency injection, and a comprehensive testing setup, all out of the box.

🤔 Why is it needed?

  • HTML is static: Plain HTML has no built-in data binding, component model, or routing.
  • DOM manipulation is error-prone: jQuery/vanilla JS leads to spaghetti code in complex UIs.
  • MVC separation of concerns: Angular enforces clean separation of view (template), logic (component), and data (service).
  • Two-way data binding: Automatically synchronizes model and view, eliminating tedious DOM queries.
  • Scalability: Provides a structured, opinionated architecture that scales for large enterprise teams.
  • TypeScript-first: Static typing catches bugs at compile time and improves IDE tooling and refactoring.

🌐 Real-time Example

    
An e-commerce SPA (like Amazon or Flipkart) built in Angular serves a single index.html. When the user navigates from the product list to their cart, Angular Router swaps components without a page reload. The ProductListComponent fetches product data from a REST API via HttpClient, displays it with *ngFor, and pushes user actions to a shared CartService via dependency injection — all while the URL updates to reflect the current view.

    

  


  

    
⚙️ Internal Working

    
Angular bootstraps via main.ts, calling bootstrapApplication(AppComponent, appConfig) for standalone apps. Zone.js monkey-patches browser async APIs (setTimeout, Promises, DOM events) so Angular knows when to run change detection — comparing the current component state against the previous rendered state and updating only the changed DOM nodes. The Ivy compiler pre-compiles templates into optimized JavaScript rendering instructions at build time. The hierarchical Dependency Injection tree resolves service dependencies via constructor injection, creating singleton or scoped instances as configured.

❌ Disadvantages

      
    
        
  • Steep learning curve — decorators, DI, RxJS, Signals, modules all at once
    • 
        
  • Verbose boilerplate compared to React or Vue for simple components
    • 
        
  • Heavier initial bundle than a minimal React app
    • 
        
  • Frequent major version releases require regular migration effort
    • 
        
  • Complex state management for large apps still requires NgRx or similar
    • 
      

    

  


  

    
🏆 Best Practices

    
    
      
  • Use the Angular CLI for all project generation — never create files manually
    • 
      
  • Follow Angular Style Guide naming conventions (kebab-case files, PascalCase classes)
    • 
      
  • Use standalone components (Angular 15+) to avoid NgModule overhead
    • 
      
  • Keep components small and single-responsibility; push logic to services
    • 
      
  • Use lazy loading for feature routes to optimize initial load time
    • 
      
  • Always unsubscribe from Observables (takeUntilDestroyed, AsyncPipe) to prevent memory leaks
    • 
    

  


  

    
⚠️ Common Mistakes

    
    
      
  • Putting business logic directly inside components instead of services
    • 
      
  • Forgetting to import CommonModule or FormsModule in standalone components
    • 
      
  • Not using OnPush change detection for performance-sensitive components
    • 
      
  • Subscribing to Observables manually without unsubscribing (memory leaks)
    • 
      
  • Ignoring TypeScript strict mode, reducing the benefit of compile-time safety
    • 
      
  • Confusing Angular (2+) with AngularJS (1.x) in interviews
