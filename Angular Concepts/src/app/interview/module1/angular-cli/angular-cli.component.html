Angular CLI

The official command-line tool for scaffolding, building, testing, and maintaining Angular applications.

📌 Definition

The Angular CLI (Command Line Interface) is an official Node.js-based tool maintained by the Angular team for automating every aspect of Angular development. It provides commands to create new projects, generate code artifacts (components, services, modules, pipes), serve locally with hot reload, build for production, run tests, and add third-party libraries via schematics — all with best-practice configuration baked in, so teams can focus on writing application code rather than build tooling.

🤔 Why is it needed?

  • Eliminates build configuration: Webpack/esbuild, TypeScript, Karma, and ESLint are pre-configured — no manual setup.
  • Consistent scaffolding: Generated files follow naming conventions and boilerplate automatically.
  • Reduces human error: Developers don't forget to declare components or add import statements — the CLI does it.
  • Unified workflow: One tool for development, testing, building, and deploying across the entire team.
  • Schematics ecosystem: Third-party libraries (NgRx, Angular Material) provide their own ng add schematics for auto-configuration.
  • Build optimization: Production builds include tree-shaking, minification, lazy chunking, and differential loading automatically.

🌐 Real-time Example

    
A team starting a new e-commerce Angular project runs ng new ecommerce-app --routing --style=scss --strict to scaffold the full project in under a minute. They run ng add @angular/material to set up Angular Material with theme, fonts, and animations configured. Feature developers run ng g c features/products/product-list and the CLI creates all 3 files and updates any relevant module or config — no manual boilerplate. Before each release, ng build --configuration=production generates optimized, gzip-compressed bundles ready for deployment to a CDN.

    

  


  

    
⚙️ Internal Working

    
The Angular CLI uses Angular DevKit (a collection of tools: Architect, Schematics, and Workspace) under the hood. ng serve uses esbuild (since Angular 16) as the module bundler and Vite as the development server, providing millisecond-fast incremental rebuilds via native ES module hot replacement. ng build runs the full compilation pipeline: TypeScript type checking → Ivy template compilation → esbuild bundling → minification → bundle budget analysis. ng generate uses Schematics — code transformation scripts that read and modify the workspace, creating files and updating angular.json atomically.

  


  

    

      
✅ Advantages

      
    
        
  • Zero configuration — build tooling is pre-configured and maintained by the Angular team
    • 
        
  • Consistent code generation ensures naming conventions and boilerplate are always correct
    • 
        
  • Automated library setup with ng add schematics
    • 
        
  • Built-in bundle size budgets — warns/errors when bundles exceed thresholds
    • 
        
  • Environment-specific builds via file replacements
    • 
        
  • Fast rebuilds with esbuild and incremental compilation
    • 
      

    

    

      
❌ Disadvantages

      
    
        
  • Abstracts the underlying build tools — harder to debug edge-case build issues
    • 
        
  • Customizing webpack configuration requires builders or ejecting (complex)
    • 
        
  • CLI updates can introduce breaking changes in build behavior
    • 
        
  • Large node_modules — CLI dependencies add to project weight
    • 
        
  • Not flexible enough for highly customized monorepo setups (use Nx instead)
    • 
      

    

  


  

    
🏆 Best Practices

    
    
      
  • Always use ng generate rather than creating files manually — it updates config files automatically
    • 
      
  • Use --dry-run flag to preview what ng generate will create before committing
    • 
      
  • Set bundle size budgets in angular.json to catch bundle bloat early
    • 
      
  • Use ng update for all Angular version upgrades — never update packages manually
    • 
      
  • Enable strict mode (--strict) when creating new projects
    • 
      
  • Use --skip-tests sparingly — always generate spec files for testability
    • 
    

  


  

    
⚠️ Common Mistakes

    
    
      
  • Creating component files manually without running ng g component
    • 
      
  • Running npm install @angular/material instead of ng add @angular/material — missing auto-configuration
    • 
      
  • Not using ng update for Angular upgrades, leading to version mismatches
    • 
      
  • Ignoring bundle size budget warnings in production builds
    • 
      
  • Using ng eject (deprecated) to expose webpack config — use custom builders instead
    • 
      
  • Running ng build without --configuration=production and deploying the dev build
    •
