Module 9 — Forms

FormArray

Dynamic list of form controls — add or remove fields at runtime

📌 Definition

FormArray manages an ordered list of AbstractControl instances (FormControl, FormGroup, or nested FormArray). Unlike FormGroup, controls are indexed numerically rather than keyed by name. It is ideal for dynamic, repeating form sections where the number of inputs is unknown at design time.

🤔 Why is it needed?

  • Handles an unknown number of inputs at design time — skills, addresses, invoice items that users can add or remove
  • Provides a clean push/removeAt/insert API for runtime modifications without rebuilding the entire form
  • Aggregates validity across all items — the FormArray is valid only if every contained control is valid
  • Pairs cleanly with the formArrayName directive and *ngFor for a minimal, maintainable template pattern

🌐 Real-time Example

    
A user profile form allows candidates to list an arbitrary number of skills. Each skill is a FormControl inside a FormArray. Users can add a new skill input with a button or remove any existing one, with the form remaining valid only when every skill field is non-empty.

    

  


  

    
⚙️ Internal Working

    
FormArray extends AbstractControl, just like FormGroup. Internally it maintains an ordered array of child AbstractControl references. When push() or removeAt() is called, Angular updates the internal controls array and recalculates the aggregate value (an array of child values) and the aggregate validity status. The formArrayName directive in the template bridges the DOM to the FormArray, and [formControlName]="i" maps each input to its index position in the array.

  


  

    

      
✅ Advantages

      
    
        
  • Fully dynamic — controls are added and removed at runtime without reinitialising the form
    • 
        
  • Aggregate validity and value — form.value automatically includes all array items as an array
    • 
        
  • Composable — supports FormArray of FormGroups for complex repeating sections with multiple fields per row
    • 
      

    

    

      
❌ Disadvantages

      
    
        
  • Controls are index-based, not named — losing track of the index in complex UIs can cause binding errors
    • 
        
  • Requires a typed getter and a cast (as FormArray) because FormGroup.get() returns AbstractControl
    • 
      

    

  


  

    
🏆 Best Practices

    
    
      
  • Always expose the FormArray through a typed getter method to avoid repeated casting throughout the component
    • 
      
  • Add a minimum-length validator directly on the FormArray to enforce at least one entry when required
    • 
      
  • Use FormArray of FormGroups when each dynamic row has more than one field to keep the model clean and typed
    • 
    

  


  

    
⚠️ Common Mistakes

    
    
      
  • Directly pushing to controls array instead of using the FormArray API — this bypasses Angular's change detection
    • 
      
  • Forgetting the formArrayName directive in the template, causing the form binding to silently fail
    •
