Module 14 — Interceptors

Token Interceptor

Automatically attaches the Bearer JWT to every API request — auth header injection as a cross-cutting concern

📌 Definition

A Token Interceptor is an Angular HTTP interceptor with the single responsibility of reading the current authentication token (JWT) and attaching it as an Authorization: Bearer <token> header to every outgoing HTTP request. Instead of each service method manually adding the auth header, the interceptor handles it transparently — the service calls http.get("/api/data") and the token is added automatically. This is the most common real-world interceptor implementation.

🤔 Why is it needed?

  • DRY — add the Authorization header once, applies to all API calls
  • Services stay clean — no token management code in service methods
  • Easily update token logic (e.g., switch storage strategy) in one place
  • Can skip specific endpoints (login, register) using HttpContext tokens
  • Reads token from a centralized AuthService — single source of truth

🌐 Real-time Example

    
An AuthService stores the access token in memory (safest against XSS). The token interceptor reads from AuthService.getAccessToken(), checks a list of public URLs (login, register), and attaches the Bearer token to all other requests using req.clone({ setHeaders: ... }). Public endpoint calls use HttpContext with SKIP_AUTH = true for explicit opt-out.

    

  


  

    
⚙️ Internal Working

    
When HttpClient makes a request, it passes the HttpRequest through the interceptor chain in registration order. The token interceptor runs, reads the current token from AuthService, calls req.clone() to create a new immutable request with the Authorization header added, and passes the cloned request to next(authReq). The next interceptor in the chain (or the HttpBackend) receives the request already containing the header. The token is read synchronously from memory — no asynchronous operation needed.

  


  

    

      
✅ Advantages

      
    
        
  • Zero boilerplate in service methods — all services benefit automatically
    • 
        
  • Centralized token read logic — change storage strategy once
    • 
        
  • HttpContext tokens enable clean opt-out for public endpoints
    • 
        
  • Works with functional interceptors and inject() for clean DI
    • 
        
  • Simple, synchronous, fast — no RxJS operators needed for basic token attachment
    • 
      

    

    

      
❌ Disadvantages

      
    
        
  • Applies to ALL HttpClient calls — needs explicit skipping for public/third-party URLs
    • 
        
  • Does not handle token expiry — needs a paired error interceptor for 401 refresh
    • 
        
  • URL-based skipping is fragile — endpoint URLs change across environments
    • 
        
  • Attaches token even to third-party API calls if not guarded (e.g., calls to external CDNs)
    • 
      

    

  


  

    
🏆 Best Practices

    
    
      
  • Use HttpContextToken (SKIP_AUTH) for opt-out rather than URL string matching
    • 
      
  • Read the token from an AuthService memory property — not directly from localStorage
    • 
      
  • Use setHeaders shorthand in req.clone() — preserves existing headers automatically
    • 
      
  • Guard against adding token to third-party URLs: check req.url.startsWith(environment.apiUrl)
    • 
      
  • Keep the token interceptor focused on attachment only — delegate refresh logic to an error interceptor
    • 
      
  • Register token interceptor before error interceptor in the chain
    • 
    

  


  

    
⚠️ Common Mistakes

    
    
      
  • Reading token directly from localStorage in the interceptor — should use a service abstraction
    • 
      
  • Sending the token to third-party domains — leaks the token to external servers
    • 
      
  • Not skipping the token interceptor for login/register — causes unnecessary 401 on login failures
    • 
      
  • Trying to handle token refresh inside the token interceptor — creates circular complexity
    • 
      
  • Forgetting to guard against null token — throws when user is not authenticated
    •
