Module 13 — Authentication

JWT — JSON Web Token

Stateless authentication token: a compact, self-contained credential carrying signed claims

📌 Definition

A JSON Web Token (JWT) is an open standard (RFC 7519) for securely transmitting information between parties as a JSON object. It is self-contained — the token itself carries the user's identity and claims (roles, expiry, user ID) without requiring the server to look up a session in a database on every request. JWTs are signed (not encrypted) using a secret key (HS256) or public/private key pair (RS256), enabling the server to verify authenticity without storing session state.

🤔 Why is it needed?

  • Stateless authentication — no server-side session store needed (scales horizontally)
  • Works across microservices — each service can independently verify the token
  • Self-contained claims — roles, permissions, expiry all in the token itself
  • Standard format — supported by every major language and framework
  • Ideal for SPAs and mobile apps where cookies are harder to manage

🌐 Real-time Example

    
An Angular app authenticates users via a login API that returns a JWT. An HTTP interceptor reads the token (from memory or httpOnly cookie) and attaches it as a Bearer token in the Authorization header of every outgoing API request. The backend validates the signature and extracts user claims without querying a session database.

    

  


  

    
⚙️ Internal Working

    
When a user logs in, the server creates a JWT by: (1) encoding the header and payload as Base64Url strings; (2) computing HMAC-SHA256(header + "." + payload, serverSecret) for the signature; (3) concatenating all three with ".". When an API request arrives with the token, the server re-computes the signature using its secret and compares it — if they match, the token is valid. The server also checks the exp claim against the current time. If either check fails, a 401 is returned. The server never needs to query a database for session data.

  


  

    

      
✅ Advantages

      
    
        
  • Stateless — server doesn't need a session store (ideal for distributed systems)
    • 
        
  • Self-contained — all user info in the token, eliminates per-request DB lookups
    • 
        
  • Cross-domain friendly — easily sent as an Authorization header
    • 
        
  • Scales horizontally — any server instance can validate any JWT
    • 
        
  • Rich claims support — roles, permissions, tenant ID, all encoded in the token
    • 
      

    

    

      
❌ Disadvantages

      
    
        
  • Cannot be revoked server-side before expiry (unless using a token blacklist)
    • 
        
  • Payload is only encoded — never store secrets or PII in it
    • 
        
  • Larger than session IDs — increases request header size
    • 
        
  • localStorage storage is XSS-vulnerable
    • 
        
  • Logout requires client-side token deletion (no server-side session to destroy)
    • 
      

    

  


  

    
🏆 Best Practices

    
    
      
  • Store JWTs in httpOnly, SameSite=Strict cookies for XSS protection
    • 
      
  • Keep access token expiry short (15 minutes) and use refresh tokens for longevity
    • 
      
  • Never store sensitive data (passwords, PII) in the JWT payload
    • 
      
  • Use RS256 (asymmetric) in microservices — other services verify without the signing secret
    • 
      
  • Always validate the token on the server — never trust client-side JWT decoding for auth decisions
    • 
      
  • Add an Angular HTTP interceptor to attach the token automatically to all API calls
    • 
    

  


  

    
⚠️ Common Mistakes

    
    
      
  • Storing JWT in localStorage — XSS attack can steal the token
    • 
      
  • Setting very long expiry (days/weeks) on access tokens — increases breach window
    • 
      
  • Trusting JWT payload claims on the client for security decisions
    • 
      
  • Not validating the token signature on the server (accepting any well-formed JWT)
    • 
      
  • Forgetting to handle 401 responses from expired tokens in the Angular interceptor
    •
