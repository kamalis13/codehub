Module 12 — Lifecycle Hooks

ngDoCheck

Custom change detection — fires every CD cycle, detecting mutations that Angular's default mechanism misses

📌 Definition

ngDoCheck is an Angular lifecycle hook called on every change detection cycle. It is Angular's escape hatch for implementing custom change detection beyond what ngOnChanges provides. While ngOnChanges only detects reference changes on @Input() properties, ngDoCheck can detect mutations within objects and arrays using Angular's KeyValueDiffers and IterableDiffers services.

🤔 Why is it needed?

  • Detects mutations inside objects and arrays (ngOnChanges cannot)
  • Enables custom diffing logic using KeyValueDiffer and IterableDiffer
  • Angular itself uses it internally for NgFor (IterableDiffer) and NgClass (KeyValueDiffer)
  • Allows derived state recalculation when mutable data changes in place
  • Provides a hook into every CD cycle for monitoring and debugging purposes

🌐 Real-time Example

    
A shopping cart component receives an items array as @Input(). The parent mutates items in-place (pushing new items, changing quantities). Since the array reference never changes, ngOnChanges never fires. ngDoCheck with IterableDiffer detects the internal mutations and recalculates the cart total efficiently.

    

  


  

    
⚙️ Internal Working

    
Angular's change detection runs as a tree walk from root to leaf components. For every component in the tree, Angular calls ngDoCheck() regardless of whether anything changed — it is always called. KeyValueDiffer and IterableDiffer maintain an internal snapshot of the last-seen state and compute a diff in O(n) time on each call. The differ only reports changes if something actually changed, so your if (changes) guard prevents unnecessary work. Angular's built-in structural directives (*ngFor, NgClass, NgStyle) all implement DoCheck and use Differs internally.

  


  

    

      
✅ Advantages

      
    
        
  • Detects deep mutations that ngOnChanges cannot see
    • 
        
  • Works with Angular's efficient Differ infrastructure (O(n) diffing)
    • 
        
  • Fine-grained control — you decide exactly what constitutes a "change"
    • 
        
  • Used by Angular internals — battle-tested approach for custom CD
    • 
        
  • Compatible with both Default and OnPush change detection strategies
    • 
      

    

    

      
❌ Disadvantages

      
    
        
  • Fires extremely frequently — every CD cycle, even when nothing changed
    • 
        
  • Heavy logic in ngDoCheck directly impacts rendering performance
    • 
        
  • Boilerplate-heavy — requires injecting Differs and creating differ instances
    • 
        
  • Easy to introduce performance regressions if misused
    • 
        
  • Cannot be used alongside ngOnChanges on the same property effectively
    • 
      

    

  


  

    
🏆 Best Practices

    
    
      
  • Always use KeyValueDiffer or IterableDiffer — never compare manually in a loop inside ngDoCheck
    • 
      
  • Guard with if (changes) before acting — the differ returns null if nothing changed
    • 
      
  • Keep all logic inside ngDoCheck extremely fast — it runs on every CD cycle
    • 
      
  • Prefer immutable data patterns over ngDoCheck whenever possible
    • 
      
  • Combine with ChangeDetectionStrategy.OnPush to reduce how often it fires
    • 
      
  • Never make HTTP calls or trigger side effects directly in ngDoCheck
    • 
    

  


  

    
⚠️ Common Mistakes

    
    
      
  • Writing heavy logic (loops, computations) directly in ngDoCheck without Differs
    • 
      
  • Making HTTP calls inside ngDoCheck — triggers on every event, causing API floods
    • 
      
  • Forgetting to initialize the Differ in the constructor before using it in ngDoCheck
    • 
      
  • Using ngDoCheck when ngOnChanges would suffice (immutable data approach)
    • 
      
  • Not guarding with if (changes) — running downstream logic on every CD cycle unnecessarily
    •
