Module 12 — Lifecycle Hooks

ngAfterViewChecked

Called after every view change detection pass — use guard flags to avoid costly DOM work on every cycle

📌 Definition

ngAfterViewChecked is an Angular lifecycle hook that fires after every change detection cycle that checks the component's view and all its child component views. It is the recurring counterpart to ngAfterViewInit (one-time). Because it fires on every CD cycle — which can happen dozens of times per second in a busy app — it must contain only the lightest possible logic, ideally guarded by a condition flag to prevent unnecessary DOM operations.

🤔 Why is it needed?

  • Post-render DOM operations that must run after every view update (e.g., scroll to bottom)
  • Measuring DOM dimensions (getBoundingClientRect) after content changes
  • Syncing a third-party library's display after Angular updates the view
  • Detecting when dynamically rendered content has settled and performing final adjustments
  • Monitoring view state changes that need immediate DOM-level reactions

🌐 Real-time Example

    
A live log viewer displays streaming server logs and must auto-scroll to the latest entry. The component tracks whether new logs were added using a prevLogCount comparison. Only when the count changes and autoScroll is enabled does it perform the actual DOM scroll — making it efficient even though ngAfterViewChecked fires on every CD cycle.

    

  


  

    
⚙️ Internal Working

    
In Angular's CD pipeline, for each component the sequence (after first init) is: ngDoCheck → ngAfterContentChecked → ngAfterViewChecked. This runs for every component in the tree on every CD cycle. ngAfterViewChecked is called last in this sequence — after both the content and view have been checked. In development mode, Angular runs an additional verification pass after calling this hook, which is why modifying bound state here without detectChanges() throws ExpressionChangedAfterItHasBeenCheckedError.

  


  

    

      
✅ Advantages

      
    
        
  • Guaranteed to fire after every view render — never misses an update
    • 
        
  • @ViewChild references are always available here
    • 
        
  • Works for post-render operations that cannot be expressed as bindings
    • 
        
  • Can be made efficient with guard flags (check condition before doing DOM work)
    • 
        
  • Consistent, predictable position in the lifecycle sequence
    • 
      

    

    

      
❌ Disadvantages

      
    
        
  • Fires extremely frequently — every CD cycle for every event in the app
    • 
        
  • Unguarded logic causes significant performance degradation
    • 
        
  • Modifying bound state causes ExpressionChangedAfterItHasBeenCheckedError in dev mode
    • 
        
  • Overuse is a code smell — often indicates missing reactive patterns
    • 
        
  • Difficult to debug performance regressions caused by heavy ngAfterViewChecked logic
    • 
      

    

  


  

    
🏆 Best Practices

    
    
      
  • Always use a guard flag or state comparison to avoid running logic on every cycle
    • 
      
  • Reset the guard flag immediately after performing the DOM operation
    • 
      
  • Use ChangeDetectorRef.detectChanges() when you must modify bound state inside this hook
    • 
      
  • Prefer ChangeDetectionStrategy.OnPush to reduce how frequently this hook fires
    • 
      
  • Consider MutationObserver or Angular CDK as cleaner alternatives for DOM monitoring
    • 
      
  • Implement implements AfterViewChecked for TypeScript type enforcement
    • 
    

  


  

    
⚠️ Common Mistakes

    
    
      
  • Running DOM operations unconditionally — causes lag on every event (mouse move, keypress)
    • 
      
  • Modifying template-bound properties without detectChanges() — ExpressionChangedError in dev
    • 
      
  • Using ngAfterViewChecked when ngAfterViewInit would suffice (one-time setup)
    • 
      
  • Placing API calls or complex computations here
    • 
      
  • Forgetting to reset the guard flag, causing the operation to run only once
    •
