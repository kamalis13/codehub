Module 12 — Lifecycle Hooks

Constructor

The first method called when Angular creates a component — used exclusively for Dependency Injection

📌 Definition

The constructor is a standard TypeScript/JavaScript class method invoked by Angular's component factory when instantiating a component. It is the very first entry point in a component's lifecycle — before any lifecycle hooks, before @Input() values are resolved, and before the view is rendered. Angular's DI framework reads the constructor's parameter types (via TypeScript metadata) and injects the matching service instances automatically.

🤔 Why is it needed?

  • Enables Angular's Dependency Injection — services are injected as typed constructor parameters
  • Establishes service references before any lifecycle hook runs
  • Allows use of @Inject for InjectionToken-based dependencies (non-class tokens)
  • Makes all component dependencies explicitly visible in one place
  • Supports @Optional, @Self, @SkipSelf, @Host modifiers for fine-grained injection control

🌐 Real-time Example

    
In an e-commerce dashboard, the constructor injects OrderService, AuthService, and a custom CONFIG_TOKEN via @Inject. A synchronous role check is acceptable in the constructor; the async HTTP call for orders is deferred to ngOnInit() where @Input() values are guaranteed to be set.

    

  


  

    
⚙️ Internal Working

    
When Angular's component factory creates a component, it calls new ComponentClass(...deps) where each dependency is resolved by Angular's hierarchical injector. The injector walks up from the component-level injector → module injector → root injector, finding a provider for each constructor parameter token. After instantiation, Angular begins the change detection cycle and calls ngOnChanges (if inputs exist) then ngOnInit. TypeScript's emitDecoratorMetadata option causes the compiler to emit type metadata that Angular reads to identify injection tokens.

  


  

    

      
✅ Advantages

      
    
        
  • Clean, explicit declaration of component dependencies
    • 
        
  • TypeScript type inference works seamlessly — no runtime type errors
    • 
        
  • Services are available immediately in ngOnInit and other hooks
    • 
        
  • Supports @Inject, @Optional, @Self, @SkipSelf, @Host decorators
    • 
        
  • Familiar OOP pattern — every TypeScript developer understands constructors
    • 
        
  • Modern alternative: inject() function (Angular 14+) works in field initializers too
    • 
      

    

    

      
❌ Disadvantages

      
    
        
  • @Input() values are NOT available in the constructor
    • 
        
  • DOM and @ViewChild / @ContentChild references are not yet initialized
    • 
        
  • Heavy logic in constructor complicates unit tests (runs during instantiation)
    • 
        
  • Cannot conditionally skip service injection without complex workarounds
    • 
        
  • SSR (Angular Universal) can be affected by side-effects in constructors
    • 
      

    

  


  

    
🏆 Best Practices

    
    
      
  • Use the constructor only for dependency injection — no logic
    • 
      
  • Declare injected services with private readonly or protected readonly
    • 
      
  • Move all initialization logic (HTTP, subscriptions, DOM) to ngOnInit()
    • 
      
  • Use @Inject(TOKEN) for InjectionToken dependencies; omit it for class-based services
    • 
      
  • Prefer inject() function in Angular 14+ for standalone functions and composable patterns
    • 
      
  • Keep the constructor body empty — services auto-assign via TypeScript shorthand (private svc: SvcClass)
    • 
    

  


  

    
⚠️ Common Mistakes

    
    
      
  • Making HTTP calls in the constructor — @Input() values not yet available
    • 
      
  • Accessing this.elementRef.nativeElement in constructor — DOM not created yet
    • 
      
  • Subscribing to Observables in the constructor instead of ngOnInit
    • 
      
  • Forgetting @Inject when injecting InjectionToken values
    • 
      
  • Reading route parameters in constructor — ActivatedRoute not fully resolved yet
    •
